# Второе независимое ревью после исправлений F1–F3

Дата: 2026-09-21. Проверены исправления относительно входного снимка `baseline/` первого независимого ревью. HEAD репозитория остаётся `27757a44dec8ab97fd949e031d9bc77830caa5db`. Исходники не менялись; аппаратная плата не использовалась.

## Результат

Все три замечания первого прохода закрыты. Новых подтверждённых дефектов или регрессий в проверенных исправлениях не обнаружено.

| Замечание | Результат независимой проверки |
|---|---|
| F1, P1: потеря SAFE при UART overflow | Закрыто. Тот же прежний reproducer на исправленном ISR теперь даёт SAFE seq 0→1, HLG OFF, PASS. Дополнительный случайный тест 200 IRQ/read потоков подтверждает доставку всех завершённых достоверных SAFE ровно один раз без ложных SAFE. |
| F2, P2: старый контракт update в UI/emulator | Закрыто. Backend/frontend ограничены 768 KiB и требуют CFG2. Независимый Python harness проверил legacy markers `ffffffff`, `00000000`, `31474643` → отказ UI и `ERR:UPD_HEADER,layout` в emulator; CFG2 → UI accept и COMMIT OK. Размеры 786432/786433/819200 проверены по обеим сторонам границы. |
| F3, P2: reset эмулятора снимает внешние аварии PSU | Закрыто. После двух последовательных reset отдельно сохраняются ALARM=1, DCOK=0, DCOK=1 и DAC_FAIL=1. ALARM блокирует RSP ON; DAC_FAIL оставляет код неизвестным и SAFE step 1 FAIL. Выходы после reset выключены. |

## UART: что проверено дополнительно

Прочитаны потоковый recognizer, кольцевые `safe_end` метки, счётчики queued/recovered SAFE, poisoning неполного core-префикса и поэтапная выдача синтетических кадров при `max=1`. В ISR нет вызовов core-логики. UART FE/NE/ORE инвалидирует незавершённую физическую строку; software ring overflow сам по себе не делает неповреждённые принятые байты недостоверными. Метаданные потребляются при выключенных прерываниях и не дублируют SAFE, уже выданный основному контексту.

`repro_uart_randomized.c` использует настоящий исправленный `hal/target/console.c` под mock-регистрами. Для каждого из 200 прогонов генерируются 1500 фрагментов: правильные SAFE с пробелами/разным регистром/CR, несколько SAFE подряд, обычные запросы, неполные `SA`/`FE`, ошибочные строки и случайные UART FE. Между произвольными байтами выполняются чтения 1–64 байт с возникновением переполнений. Независимый reference parser считает завершённые достоверные SAFE исходного потока, второй parser считает кадры на выходе HAL. Во всех 200 случаях количества совпали; ложных SAFE и потерь не обнаружено.

Изменённый repository-тест дополнительно покрывает NUL, превышение CMD_LINE_MAX, реальные начальные/граничные/конечные позиции overflow и сохранение маски IRQ. Эти проверки прочитаны; полный прогон CTest/pytest не дублировался без необходимости.

## Артефакты и результаты

- `repro_uart_safe_overflow_fixed.exe`: `SAFE seq before=0 after=1; HLG on=0`, `uart_safe_overflow: OK`.
- `repro_uart_randomized.c/.exe`: `200 randomized IRQ/read streams: all valid SAFE delivered exactly once; no false SAFE`.
- `repro_model_contracts_fixed.py`: все assertions прошли, включая положительный новый образ и отрицательные legacy/oversize образы.
- Первоначальные repro и `independent-initial-review.md` сохранены для сравнения.

Основной агент отдельно сообщил 16 CTest PASS и 76 pytest PASS. Эти результаты не выдаются за независимый повторный полный прогон. Здесь использованы актуальные host static libraries без изменения core и отдельная компиляция scratch harness; CMake build репозитория не запускался. Проверка target/bringup сборок выполняется основным агентом. Новая target-прошивка в рамках этого ревью на плату не загружалась; аппаратные времена/аналоговая работа периферии данным проходом не подтверждены.

Изменённые исходники/UI и новые regression tests просмотрены. Этапы 7+ и ручные измерения не рассматривались как дефекты. По исследованному объёму дополнительных оснований требовать исправления нет.
