# Шаг 3 — реле и блокировки

Дата: 2026-09-18. Прошивка, эмулятор и интерфейс: 0.3.0.
**Программная часть реализована и загружена. Аппаратная приёмка не закрыта:**
владелец отложил прозвонку и анализатор; провод петли SR0 отсутствует.

## Реализовано

- `ROUT:HIGH`, `ROUT:LOW`, `ROUT:LOW:ALL`, `ROUT:SET`, `ROUT:STAT?`, все 81 имя.
  Регистр имён не важен, повторы идемпотентны, пустой SET выключает все.
- Проверка итоговой карты до воздействий, 12 групп и порядок 609 пар из генератора.
  Ответ `ERR:INTERLOCK,<пара>,<имя>,<имя>` совпадает с файлом платформы.
- Выключение разности, полный образ затронутой цепочки, пауза, включение разности.
  Служебные биты и остальные реле сохраняются. Без изменения карты нет записей.
  Константа паузы 20 мс; дополнительный тик исключает усечение до 19.x мс.
  Между фазами обслуживаются watchdog и связь; SAFE/потеря TCP отменяют включение.
- SR0: два уровня тестового бита и восстановление, без изменений битов реле и CS_LOAD.
  Застрявшие 0/1 дают FAIL. SR1 остаётся UNVERIFIED.
- Chrome: панель по блокам, переключатели, группы, поиск, точный список, ответ
  и подсветка конфликтующей пары, автодополнение из устройства. Отдельный терминал.
  Каталог содержит 32 команды (22 рабочих, 10 DBG).

## Автоматические проверки

- 8/8 CTest: все имена/адреса, пары групп, отказ без GPIO/SPI, пауза на MCU и SR,
  переполнение тика, SAFE/потеря клиента во время паузы, диагностика и каждый полный
  образ SR0, сохранение реле при изменении CS_LOAD.
- 57/57 pytest; синтаксис трёх JS; сборки host, target и bringup.
- 57 проверок эталонных диалогов на каждом из C и эмулятора (23 новых шага 3).
- `check_relay_contract.py`: 1385 сравнений C/эмулятора, все 609 пар, все 81 имя,
  множественный конфликт и версия/сумма таблицы. Локально использован настоящий
  `testdut.sdk.interlocks.InterlockTable.violated_group` из рабочего дерева платформы.
  В CI без установки платформы применяется её правило первого включённого подмножества
  непосредственно к `gen/interlock-table.json`.

## Плата

Ethernet через коммутатор, 192.168.0.20:5025, MAC 02:88:49:85:68:CC, COM3.
Внешние цепи отключены по подтверждению владельца. Обновление через мастер пульта,
пробный запуск подтверждён. Серийный номер не назначался.

Образ: 59872 байт, SHA-256 `a379cdf9bf6c6fffb4faab53f13936f0efb14a6310b842555343a66c346acfed`.

Проверены из пульта: установка каждого имени, чтение карты, TEST:ALL? без изменения
карты, выключение и пустая карта. Это подтверждение команд и внутреннего образа,
**не** замыкания контактов. В браузере проверены M4 ON, отказ M5, SET M5,
подсветка и фильтр RA. По COM проверены блокировка, замена M4/M5, запрет установки
при TCP-владельце, сброс карты при новом TCP-подключении и SAFE.

Полный диалог на плате остановлен на 11-й проверке: вместо ожидаемого SR0:OK
получен SR0:FAIL. Владелец подтвердил отсутствие провода петли. Последующие отдельные
проверки всех 81 имени выполнены с сохранением FAIL. Отчёты: [TCP](step-3-board.json),
[COM](step-3-console.json). Финал: SAFE → OK, ROUT:STAT? пусто.

## Осталось с разработчиком платы

1. Установить провод SR0.2.E → PB7 и повторить TEST:ALL?; ожидается SR0:OK,
   SR1:UNVERIFIED. Проверить под анализатором отсутствие переходов реле при тесте.
2. Прозвонить все 81 реле по таблице при ON/OFF и записать соответствие контактов.
3. Снять M4 → M5 и пару одной цепочки (например M11 → M12): выключение раньше
   включения, разрыв не меньше 20 мс. Уточнить константу по паспорту и измерению.
4. Проверить анализатором отсутствие переходов реле при обмене через CS_LOAD.
   Хост-проверка есть; контроллер нагрузок и его штатный обмен относятся к шагу 7.

Предшествующие незакрытые измерения и ограничения шагов 1–2 этим протоколом
не снимаются. CI для коммита проверяется отдельно после публикации.
